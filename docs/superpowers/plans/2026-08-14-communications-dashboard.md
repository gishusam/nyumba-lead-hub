# Communications Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a responsive Communications workspace matching the supplied campaign-dashboard reference, accessible from the existing Nyumba Zetu application shell.

**Architecture:** Add one route-local presentational module with deterministic campaign data, keeping campaign metrics and the selected campaign in typed local state because the existing API has only lead-level email endpoints and no campaign contract. Reuse the locked shadcn primitives, chart library, application shell, tokens, and existing responsive navigation.

**Tech Stack:** React 19, TypeScript, TanStack Router, Tailwind CSS v4, shadcn primitives, Recharts, Lucide.

## Global Constraints

- Reproduce the supplied reference's dense campaign overview, list, selected-campaign detail, delivery-domain breakdown, and campaign-type composition.
- Do not invent or call a campaign API: no backend campaign endpoint exists in the frontend's current API contract.
- Retain the locked Nyumba visual system: calm white surfaces, emerald primary actions, compact utility text, restrained borders, and semantic delivery colors.
- Add the navigation route in both desktop and mobile through the shared AppSidebar source of truth.
- Make visible interactions truthful: campaign selection and pagination update the detail view; the New Campaign action explicitly says that campaign creation requires a campaign service rather than pretending to send email.
- Verify at desktop and narrow mobile viewports, with no horizontal page overflow.
